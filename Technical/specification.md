# Technical Presentation Design Specification

## Overview
Clear and detailed presentation design for technical documentation, architecture reviews, engineering presentations, and developer conferences.

## Design Principles
- **Precision**: Accurate and detailed technical information
- **Clarity**: Complex concepts explained simply
- **Logical**: Information flows in logical sequence
- **Practical**: Code examples and real implementations

## Color Palette
- **Background**: Dark themes for code readability (#1E1E1E, #2D2D30)
  - Alternative: Light themes (#FFFFFF) for general content
- **Syntax Highlighting**: Standard code color schemes
  - Keywords: #569CD6 (blue)
  - Strings: #CE9178 (orange)
  - Comments: #6A9955 (green)
  - Functions: #DCDCAA (yellow)
- **Accent Colors**: Tech-oriented colors (blue, green, cyan)
- **Status Indicators**: Red (error), Yellow (warning), Green (success)

## Typography
- **Headings**: Clear, technical fonts
  - Title: 36-40pt, Bold
  - Section Headers: 28-32pt, Semi-bold
  - Code Headers: 24-28pt, Regular
- **Body Text**: 16-20pt, Regular
- **Code Blocks**: Monospace fonts (Fira Code, Source Code Pro, Consolas)
  - Inline code: 14-16pt
  - Code blocks: 12-14pt with line numbers

## Layout Guidelines
- **Code Blocks**: Adequate space for readability
- **Margins**: Standard 0.5" margins
- **Two-Column**: Use for before/after comparisons
- **Diagrams**: Full slide for complex architectures
- **Reference Area**: Footer for documentation links

## Slide Structure
1. **Title Slide**: Project name, version, presenter, contact
2. **Agenda/Outline**: Technical topics to cover
3. **Architecture Overview**: High-level system design
4. **Technical Details**: Deep dive into components
5. **Code Examples**: Working implementations
6. **Performance Metrics**: Benchmarks and measurements
7. **Challenges/Solutions**: Problems encountered and resolutions
8. **Next Steps**: Future work and roadmap
9. **Q&A**: Questions and discussion
10. **References**: Links to docs, repos, resources

## Visual Elements
- **Architecture Diagrams**: System components and relationships
- **Sequence Diagrams**: Process flows and interactions
- **Code Snippets**: Syntax-highlighted examples
- **Screenshots**: Terminal output, UI states, debugging
- **Flowcharts**: Algorithm logic and decision trees
- **Network Diagrams**: Infrastructure and connectivity
- **Data Models**: Database schemas and relationships
- **API Documentation**: Endpoints and parameters

## Code Display Best Practices
- Use syntax highlighting consistently
- Include line numbers for reference
- Highlight changed/important lines
- Keep code snippets focused (10-20 lines max)
- Add comments for clarity
- Show input and output examples
- Use diff view for changes

## Diagram Guidelines
- Use standard notation (UML, C4, etc.)
- Label all components clearly
- Show data flow with arrows
- Use color to distinguish layers/types
- Include legends for symbols
- Keep diagrams uncluttered

## Technical Content
- Include version numbers and dependencies
- Show command-line examples
- Provide error handling examples
- Document API endpoints
- Include performance benchmarks
- Show test coverage and results
- Reference documentation and standards

## Best Practices
- Start with overview, then details
- Use progressive disclosure for complex topics
- Include live demos when possible
- Provide code repositories and links
- Add speaker notes with technical details
- Include troubleshooting tips
- Reference industry standards
- Show real-world use cases

## Accessibility for Developers
- High contrast for code readability
- Readable font sizes for projectors
- Provide code samples in repository
- Include alternative text formats
- Share slides before presentation

## File Requirements
- **Format**: .pptx or Markdown for developers
- **Resolution**: 1920x1080 (16:9 aspect ratio)
- **Code Samples**: Include separate files or gists
- **Diagrams**: Export as SVG for quality
- **Naming Convention**: `Project_Topic_YYYY-MM-DD.pptx`
